# 完整体验样例

初始条件：PowerContext 和游戏网关已启动；Dify 已导入并发布 Chatflow；选一个此前未使用的玩家编号，例如 `rain_guest_001`。每次测试换一个新编号即可恢复初始状态。

1. 打开 Dify 聊天页面，填写玩家编号 `rain_guest_001`，发送“老板，我想借走红伞”。预期：阿墨围绕借伞作出回应并给出下一步选择。HTTP 节点的响应中 `event` 是“玩家从便利店借走红伞，约定下次归还。”，`saved_records` 非空。
2. 在 Dify 中开启**新会话**，仍填写 `rain_guest_001`，只发送“老板，我又来了”。预期：阿墨主动提起之前借走的红伞；HTTP 响应 `memory_status` 为 `ready`，`memory` 含借伞事实，`event` 为空。第二次输入不包含“红伞”，因此可以证明信息来自跨会话召回。
3. 再开启新会话，改填 `other_guest_001`，只发送“老板，我又来了”。预期：HTTP 响应 `memory_status` 为 `empty` 或 `memory` 不含借伞事实；阿墨不提起其他玩家的红伞。
4. 回到 `rain_guest_001`，发送“我来归还红伞”。预期：出现归还事件，阿墨感谢玩家。可在节点响应中看到 `saved_records`，并在 PowerContext 读写记录中核对该事件。

保留以上四步的 Dify 节点执行截图或日志、PowerContext 返回的记忆记录以及应用最终输出。LLM 用开放式文本回复，台词没有唯一标准答案；验证点是事件写入、同一玩家跨会话召回、不同玩家隔离，以及剧情随历史变化。
